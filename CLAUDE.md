# Anvil UI — project guide for Claude Code

Anvil UI is Zazmic's design system for conversational AI agents. This repo turns the
**Zazmic Anvil UI Kit (Design System)** Figma file into React components (shadcn/ui on
Radix, Tailwind CSS v4) documented in Storybook.

**Figma is the source of truth for design. `docs/api-contract.md` is the source of truth
for names.** Code follows both; never invent values or prop names.

Current scope: **local development only.** Do not set up hosting, Cloud Run, IAP, the shadcn
registry, the tokens package or Code Connect publishing until asked (see `docs/roadmap.md`).

---

## Stack

React 19 · Vite · TypeScript (strict) · Tailwind CSS v4 (`@tailwindcss/vite`, CSS-first
`@theme inline`, no `tailwind.config.js`) · shadcn/ui (Radix) · Storybook 9+
(`@storybook/react-vite`) · Style Dictionary 4 · pnpm. Pin exact versions when installing.
Ask before adding any dependency not listed here.

## Commands (create these in Step 1, keep them working)

```bash
pnpm dev               # Vite playground
pnpm storybook         # Storybook on http://localhost:6006
pnpm build-storybook   # static build to storybook-static/
pnpm tokens:build      # tokens/anvil.tokens.json → src/styles/tokens/*.css
pnpm lint              # ESLint + Prettier check
pnpm typecheck         # tsc --noEmit
pnpm test-storybook    # interaction + a11y tests
```

Run `pnpm typecheck && pnpm lint` before saying a task is done.

## Tokens

- Source: `tokens/anvil.tokens.json`, exported by the designer from Figma (DTCG Token Exporter
  plugin). If it is missing, **stop and ask**; do not reconstruct values from screenshots.
- CSS variable names come from each Figma variable's **code syntax (WEB)**, which already uses
  shadcn names: `--background`, `--foreground`, `--primary`, `--primary-foreground`, `--muted`,
  `--accent`, `--destructive`, `--border`, `--input`, `--ring`, `--card`, `--popover`,
  `--chart-1…5`, `--sidebar-*`. Anvil extras: `--agent*`, `--success*`, `--warning*`, `--info*`,
  `--danger*`, `--overlay` (scrim), button hover tokens, `--shell-*`.
- Collections → output: `colors` light/dark → `:root` / `.dark`; `dimensions` desktop/mobile →
  base + `@media (max-width: 767px)` override; `typography` desktop/mobile → same; `shell`
  modes → `[data-shell="full-screen" | "side-panel" | "popover" | "mobile"]`; `primitives` →
  plain variables referenced by the others.
- Transforms (recorded in the API Contract): font-weight strings → 400 / 500 / 600;
  letter-spacing in px; `radius/full` → `calc(infinity * 1px)`; radii derive from
  `--radius` (8px): `calc(var(--radius) ± n)`; spacing steps lg–4xl → `--space-*` (never
  `--spacing-*` t-shirt keys; they collide with Tailwind sizing utilities).
- Register every semantic variable in `@theme inline` as `--color-*`, `--radius-*`, `--shadow-*`,
  `--font-*` so utilities like `bg-agent-soft` work.
- Elevation: `elevation/raised` (Popover, menus, Combobox list, Date Picker, hover card) and
  `elevation/modal` (Dialog, Alert Dialog, Sheet, Drawer). Card is flat (border only).
- Dark mode: `@custom-variant dark (&:is(.dark *));` with `.dark` on `<html>`.

## API rules (full list in `docs/api-contract.md`)

- Prop names: `variant` (appearance: default · outline · ghost · link), `intent` (neutral · brand ·
  inverse · destructive), `tone` (neutral · brand · info · success · warning · destructive · agent),
  `size` (xs · sm · default · lg · icon · icon-xs · icon-sm · icon-lg), `shape`, `side`, `align`,
  `orientation`, `checked`, `pressed`, `open`, `disabled`, `loading`, `mode`.
- `type` in Figma means *which sub-component or content kind* (e.g. dropdown item type radio →
  `DropdownMenuRadioItem`). It is not a prop unless the contract says so.
- **The Figma `state` property is never a prop.** Map each value to one selector:
  hover → `hover:` · focus → `focus-visible:` · pressed → `active:` · highlighted →
  `data-[highlighted]:` · disabled → `disabled:` / `data-[disabled]:` · invalid →
  `aria-invalid:` · open → `data-[state=open]:` · active → `data-[active=true]:`.
- Focus ring: `focus/ring` = 2px `--background` gap + 4px `--ring` → `ring-2 ring-ring
  ring-offset-2 ring-offset-background` (or an equivalent `@utility focus-ring`).
- Disabled: `disabled:opacity-50` unless the Figma base component draws its own disabled look.
- Design-only Figma properties map to nothing: `show beamer`, `show highlight`, `empty`,
  `preset`, `show …` booleans (render or omit the part instead).
- **Labels:** `Label` is the single label atom. Text field, Textarea and Select have the field
  anatomy built in: with a label they render `Field` + `FieldLabel` + control +
  `FieldDescription` (or `FieldError` when invalid); without a label they are the bare control.
  Never wrap them in another Field. Use `Field` for controls without a built-in label
  (Combobox, Input OTP, Slider, groups, horizontal Switch / Checkbox rows with a description).
  Checkbox, Radio and Switch use an inline `Label`.
- **Shells:** Dialog, Alert Dialog, Sheet, Drawer, Popover and Card share `ShellHeader`
  (`variant` bar · inline; title, description, close) and `ShellFooter` (`variant` bar · inline ×
  `align` end · between · stretch; primary + secondary actions) in `components/anvil/shell`.
  The overlay (`--overlay`) is a sibling of the shell, never baked in.
- Modal is a behavior, not a component. Context Menu reuses Dropdown Menu items. Hover card is
  a Card inside `HoverCard`. Menu in Figma = `Menubar` in code. Toast = Sonner.

## Per-component workflow

1. Read the Figma page (`get_metadata`), then the component set (`get_design_context`,
   `get_screenshot`). Read its description and its rows in `docs/api-contract.md`.
2. `pnpm dlx shadcn@latest add <primitive>` when a shadcn primitive exists.
3. Restyle with `cva` using contract names and token utilities only (no hex, no px literals
   except 1px borders).
4. Write `<name>.stories.tsx` (CSF 3): Default with controls, Variants grid, Sizes, States
   (pseudo-states for hover / focus), With icons, Composition. Overlay stories: controlled
   `open`, `within(document.body)` in play functions, `parameters.docs.story.inline = false`.
   Add `parameters.design` with the Figma URL of the component set.
5. Compare against the Figma screenshot in light and dark; fix differences or note them.
6. Run `pnpm typecheck && pnpm lint && pnpm test-storybook`.
7. Update `docs/component-status.md` (component · Figma node · status · notes).

## Known Figma gaps (don't invent around them; follow the rule, note it in status)

- No focus state drawn yet on: link, card interactive, sidebar sub item, sidebar tree item →
  implement the standard focus ring anyway.
- No disabled state drawn yet on: accordion item, card interactive, search, sidebar
  conversation item, sidebar tree item → use `disabled:opacity-50`.
- Some menus and Agent Builder overlays still use `shadow/lg` directly → use `elevation/raised`.
- Search field has some hand-set colors in Figma → map to the nearest semantic token and flag it.

## Working agreements

- One component (or one foundation) per branch and PR; small, reviewable diffs.
- Never edit `tokens/` or `src/styles/tokens/` by hand.
- If Figma and `docs/api-contract.md` disagree, the contract wins; flag the mismatch.
- Ask before: adding dependencies, changing the folder structure, renaming a public prop.
- Write in plain, consistent names: "Anvil", never the old name "Obsidian".
